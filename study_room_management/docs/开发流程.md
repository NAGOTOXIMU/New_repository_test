# 开发流程：VS Code + GitHub

> 给组员的最简操作说明。**记住一句话就够了：先拉取，再改，然后暂存 → 提交 → 推送。**

---

## 一、先分清三个动作（很多人卡在这）

| 动作 | 命令 | 作用 | 类比 |
|---|---|---|---|
| **暂存** | `git add` | 挑出"这次要提交哪些改动" | 把东西放进购物车 |
| **提交** | `git commit` | 在**你自己电脑上**记一笔存档 | 结账，生成一张小票 |
| **推送** | `git push` | 把这笔存档传到 **GitHub** | 把小票上传到云端 |

⚠️ **只 `commit` 不 `push`，组员是看不到你的代码的。**

还有两个：

- **拉取** `git pull`：把 GitHub 上的最新代码取下来（开工前必做）
- **克隆** `git clone`：第一次把整个仓库下载到本地（只做一次）

---

## 二、每天的标准流程

### 第 1 次：把仓库下载到本地

```powershell
cd E:\competer_science\数据库实验test3
git clone https://github.com/NAGOTOXIMU/New_repository_test.git
```

### 每次开工前：先拉取

```powershell
cd 你的仓库目录
git pull
```

> 别跳过这步。别人改过的东西你没拉下来，等下提交就会冲突。

### 干完活：暂存 → 提交 → 推送

```powershell
git status                      # 先看改了哪些文件，确认没有多余的东西
git add .                       # 暂存所有改动（也可以 git add 具体文件名）
git commit -m "完成登录页的仓库层"   # 提交，引号里写清你干了什么
git push                        # 推到 GitHub
```

> ⚠️ **一条一行执行，不要用 `&&` 连起来。**
> VS Code 默认终端是 Windows PowerShell 5.1，它不支持 `&&`，会报
> `标记"&&"不是此版本中的有效语句分隔符`，而且**整行都不会执行**。

## 三、不想记命令？用 VS Code 图形界面

1. 左侧活动栏点 **源代码管理** 图标（像个分叉的图标，或按 `Ctrl+Shift+G`）
2. 「更改」下面会列出你改过的文件
3. 鼠标移到文件名上，点 **`+`** → 暂存
4. 上方输入框写提交说明，点 **`✓`** → 提交
5. 点 **「同步更改」** 按钮（或 `...` 菜单里的「推送」）→ 推送到 GitHub
6. **拉取**同理：`...` 菜单 → 「拉取」，或状态栏左下角的同步图标
7. **切换分支**：点左下角的状态栏（显示当前分支名的地方）

> 图形界面最大的好处：能**一眼看出改了哪些文件、哪些已暂存**，比敲命令直观。

## 四、遇到问题怎么办

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `标记"&&"不是此版本中的有效语句分隔符` | PowerShell 5.1 不支持 `&&` | 一行一条命令。想彻底解决：`Ctrl+Shift+P` → `Terminal: Select Default Profile` → 选 **PowerShell**（不带 Windows 前缀的那个，即 7.x），重开终端 |
| `warning: LF will be replaced by CRLF` | Windows 上 git 的行尾转换，**不是错误** | 不用管，不影响代码和 SQL 执行 |
| `fatal: Authentication failed` | GitHub 不再接受密码 | 跑一次 `gh auth setup-git`，之后再 `git push` |
| `Updates were rejected ... non-fast-forward` | 远端有你没拉的提交 | 先 `git pull`，处理完冲突再 `git push` |
| `git pull` 提示冲突（CONFLICT） | 你和别人改了同一处 | 在 VS Code 里打开冲突文件，会看到「接受当前更改 / 接受传入更改 / 保留两者」按钮，选好后：`git add .` → `git commit -m "解决冲突"` → `git push` |
| 不小心 `git add` 了不该提交的文件 | 比如写了密码的 `.env` | `git rm --cached 文件名`（从仓库移除但保留本地文件），然后把文件名加进 `.gitignore` |
| 想撤销还没提交的改动 | — | `git restore 文件名`（丢弃该文件的所有未提交改动，谨慎） |

## 五、提交说明怎么写

写清**做了什么**，别写"更新""修改"：

- ✅ `完成 user_repo 的查询与新增方法`
- ✅ `修复登录页密码校验失败的问题`
- ✅ `定稿 01_schema.sql：8 张表`
- ❌ `update`
- ❌ `改了一下`

---

## 六、两条团队规矩

1. **开工先 `git pull`，收工必 `git push`。** 别让代码只躺在自己电脑里。
2. **`db/sql/` 和 `repository/` 是全组公共依赖。**
   要改表结构先**在群里说**，由一个人统一改、改完通知所有人——否则别人的代码会莫名其妙全崩。

## 附：最常用的五条命令

```powershell
git pull                     # 拉取最新代码（开工前）
git status                   # 看我改了哪些文件
git add .                    # 暂存全部改动
git commit -m "说明"          # 提交到本地
git push                     # 推送到 GitHub
```
